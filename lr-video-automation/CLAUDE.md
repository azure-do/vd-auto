# CLAUDE.md

このリポジトリで作業する際の原則。

## 絶対原則

- 秘密情報（トークン/キー/シークレット/実メールアドレス/.envの値）をコード・文書・コミット・ログに一切書かない。記載可能なのはキー名・保存場所のみ。
- `docs/baseline/` は変更禁止（読み取り専用の原本）。
- 決定的コードとLLMの責務を分離する。LLMに投稿権限・トークンを渡さない。
- 現行本番（現行GAS/VideoUploaderLib）は検証完了まで停止・変更しない。
- 現行GASの完全再現を目的にしない。現行は業務ルール・実績・移行比較の参考資料とし、新システムの安全性・保守性・拡張性を優先する。
- 自社クラスマスタを講師・クラス・支部・スタジオ判定の正式な情報源とし、動画投稿側に重複マスタを作らない。
- 既存リポジトリ（`lr-portal` / `lr-line-relay`）を統合しない。ポータルの変更は既存リポジトリへのPR方式で行う。
- SEO自動化、講師ポータル、LINE・DM関連等の他プロジェクトとは、Repositoryを分離したまま共通ID・スキーマ・イベント・技術知見を共有する。
- GASとWorkerは本リポジトリで管理する（`gas/` と `worker/`）。
- Gitを正式情報源とし、GitHubではコードだけでなくADR、RFC、共通契約、横展開候補、新しい技術アイデアも管理する。リモートの新規作成・公開範囲・アクセス権変更は明示的な承認まで行わない。承認済みRepositoryの作業ブランチpushとPR提出は通常作業とする。
- このプロジェクトにおけるPMO・SE・監査の役割、委任範囲、停止点は `README.md` と `docs/runbooks/external-contributor-delivery.md` を正本とする。
- 業務要件、製品境界、認証、状態正本、個人情報、課金などの重要な未決事項は `docs/open-questions.md` で管理し、正式決定をADRへ記録する。ライブラリ、内部構造、DB製品、テーブル・index、テスト方法、PR分割などの実装判断はSEへ委任し、PRまたは必要最小限のADRへ理由を記録して進める。
- 承認済みの全体設計は `docs/design/`、共通契約は `docs/contracts/`、確定前の技術選定は `docs/rfcs/`、秘密値を含まない運用手順は `docs/runbooks/` を正とする。
- `docs/findings.md` はbaselineの再掲載ではなく、baseline作成後の新事実・差分・追加調査のみを記録する。
- `main`への直接push・Git履歴の書き換えは禁止する。作業ブランチへのpushとPR提出は、承認済み作業パッケージ内の通常作業とする。
- 外部サービスへの接続は、接続先・開発用アカウント・副作用・課金上限・停止方法を記載した作業パッケージの承認を明示的な指示とみなす。承認範囲内では操作ごとの再承認を求めず、範囲外だけ停止する。
- 外部委託者との日常運用は `docs/runbooks/external-contributor-delivery.md` を正とする。

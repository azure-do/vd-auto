# E-5.5 R2 Range／stream取得と整合性照合

- Status: implemented locally（Issue #21）
- 外部接続: なし
- 実投稿: なし

## 実装境界

`worker/src/e5-r2-stream.ts` にCloudflare R2 binding用の取得層を追加した。

1. HEADでサイズ、R2のSHA-256、ETagを取得し、承認済みメタデータと照合する。
2. 8 MiB（設定可能）のRange GETをstreamとして順次読み、incremental SHA-256で
   全byteを照合する。全量buffer、一時disk、署名URLは使わない。
3. 検証完了後だけ `VerifiedR2Source` を返す。後続処理は `open(offset)` で同じETagに
   固定されたstreamを開く。再開時はoffsetより前を取得しない。
4. `R2VerifiedSnapshot` はobject key、size、checksum、ETag、R2 versionだけのJSON化可能な
   内部契約である。別のWorker実行で承認済みsourceと全項目を照合して復元し、
   byte 0から再検証せずcommitted offsetから開く。snapshotは信頼済み運用DBに保存する。
5. HEAD後にobjectが置換された場合、条件付きRange GET、ETag、R2 version、checksum、
   object keyのいずれかが一致しないためfail-closedにする。
6. 既存 `E5PublishContractService` もこの取得層の実衅入口 `verifyR2Source()` を使う。
   E-5.1互換clientは残すが、旧のchunk配列と全量連結bufferは削除した。
7. 検証の戻り値 `VerifiedR2Source` をそのままprivate投稿dispatchに渡す。adapterには
   object keyやsnapshotを渡さず、size、checksum、`open(offset)` だけを渡す。fake publisherも
   `open(0)` のstreamを最後まで読み、増分SHA-256とbyte数の両方を再照合する。
   empty・short・overlong・途中失敗・同サイズの別内容を成功扱いにしない。
8. 各Rangeの予定byte数を受け取った後も、正常な終端（EOF）を確認する。
   最終Rangeの後続byteや終端読取エラーを成功扱いにしない。途中Rangeでも終端エラーは
   安全停止する（次のRangeの取得では、前の応答の終端を証明できないため）。
   Range途中の中断は、従来どおり未取得byteから上限付きで再試行する。
9. 消費側のcancelは終端として扱い、GETまたはbody読取の待機中でも再試行しない。
   cancel後に返ったGETのbodyも破棄し、後続byteを渡さない。

動画を外部へ送りながら最終checksumを確定すると、末尾で破損が判明するまで副作用が
進んでしまう。そのため、この層は「事前検証」と「ETag固定後の下流stream」の2-passを
採用した。R2からは2回読むが、Workerメモリにはstreamの小片だけを保持する。

## エラーと秘密情報

外部へ返すエラーは固定code、retryable、固定messageだけで、R2 SDKの例外文、object key、
署名URL、資格情報を含めない。サイズ・checksum・Range境界・ETag不一致は成功扱いにしない。

## ローカル確認

```bash
cd worker
npm ci
npm run typecheck
npm run test:e5:r2-stream
npm test
npx wrangler deploy --dry-run
```

専用テストは正常、byte破損、サイズ不一致、body中断後の未取得Range再試行、任意offset再開、
検証中のobject置換、snapshotの別objectへの差し替え、ETag/version改ざん、別Worker実行での
offset再開、検証後のobject置換、publisher側のempty・short・overlong・途中失敗、
検証時Aから送信時の同サイズBへの差し替え、秘密を含むprovider例外の非露出、
300 MiB相当のゼロbyte streamを検証する。
300 MiBテストは
64 KiBずつ動的生成し、巨大fixtureまたは巨大bufferを作らない。

最終・途中RangeのEOF確認、正しいbyte列の後の余分なbyte・終端エラーについても、
事前検証および再開streamで拒否されることを確認した。

GET成功・GET失敗・body読取の待機中にcancelする3ケースも確認した。

実行結果: 型確認成功、専用テスト22件成功、全自動テスト441件成功、
Wrangler dry-run成功。

## 後続への引渡し

E-5.6のresumable uploaderは、事前に `verify()` が成功した結果だけを受け取り、YouTubeの
committed offsetを `open(offset)` に渡す。E-5.5ではYouTube client、OAuth、session URI、
実R2、本番resourceへ接続しない。

# E-5.4 YouTube投稿の冪等フェンスと結果不明復旧

- Status: implemented locally（Issue #22）
- 外部接続: なし
- 実投稿・実動画・実OAuth: 使用なし

## 実装した境界

- 冪等キーは既存契約どおり `video_job_id + youtube + channel_id + approved_content_version` のまま固定し、`attempt_no` は別管理する。
- 各試行に非秘密の `fence_token` を割り当て、DB transaction自身が新規挿入と有効化を行った1回だけ副作用開始権を返す。同じtokenの並行呼出・再送も再許可しない。DB確定後に応答が失われた場合は、開始したか推測せず期限回収後に結果不明へ進める。
- 確定済みbyte位置、YouTube動画ID、旧sessionが使用不能かどうかを運用DBに保持する。session URI自体は本単位では取得・保存しない。
- `yt_committed_offset > 0`、`yt_video_id` 判明済み、または `RECONCILIATION_REQUIRED` の間は、新しい副作用フェンスを発行しない。
- `videos.list` 相当の偽クライアントで、private投稿の存在が確認できた場合だけ `PUBLISHED`、不存在と旧session使用不能の両方が確認できた場合だけ次の試行を許可する。確認不能時は照合待ちを維持する。
- cleanupには元のclaim tokenを必須とし、古い処理が新しいclaimを解放できないようにする。
- processing中または成功応答で動画IDが判明した時点で、結果確定より先に現在のfenceへ紐づけて保存する。結果確定と試行状態の更新は同じDB batchで行い、途中停止後も動画IDから照合できる。
- 期限切れclaimの回収では、冪等台帳と対応する試行履歴を同じ状態へ進める。照合の同時実行が競合した場合は最新状態を再読込し、成功済み・再試行可能・照合待ちのいずれかへ冪等に収束する。
- 各照合をDBへ先に登録し、`FOUND`、`NONE`、処理中、期限切れを試行単位で保持する。期限切れは結果が消えた証拠にはしない。停止・例外・確認不能で残った照合は`TIMED_OUT`として保持し、後から何回`NONE`を得ても新規投稿を許可しない。
- 期限後に返る`FOUND`も元の試行の証拠として保存する。private完了の確定は元の試行番号をDBの条件に含め、後続試行の状態は書き換えない。`FOUND`は新規副作用開始の阻止にも使う。
- 処理中・期限切れ・存在確認の証拠がなく、対象チャンネルと動画IDについて不存在が確定し、旧sessionも使用不能と確認できた場合だけ次の試行を許可する。30秒などの経過時間は不存在の証明に使わない。fakeの`not_found`はこの確定済み不存在を表す。実adapterでは空の応答、権限不足、一時的な非表示は`unknown`として扱う。
- 動画IDは一度判明した値を単調に保持し、進捗更新だけでなく成功の最終確定境界でも別IDへの差し替えを拒否する。試行状態だけを成功・失敗へ更新する公開経路は置かず、台帳・ジョブ・試行の最終状態を同じDB batchで確定する。
- YouTube成功の`resultRef`はrepository入口でも11文字の安全な動画IDだけを許可する。欠落値、任意文字列、session URIなどはDB更新前に拒否する。
- 一度保存した動画IDは同じIDでのみ更新できる。別IDが返った場合はoffsetを含め両方の運用テーブルを変更せず停止する。

## 後続への引渡し

E-5.6は暗号化したsession URIを別の秘密保管境界へ追加し、本単位の副作用フェンスを通過した場合だけsessionを発行する。E-5.7の実 `videos.list` adapterは、本単位の `YouTubeReconciliationClient` に接続する。どちらもsession URI、OAuth値、自由文字列をログ・監査へ出してはならない。

期限切れ・停止した照合が未解決のままの不存在復旧は、本単位では提供しない。E-5.7で外部の確実な証拠と照合完了条件を定義するまで照合待ちを保持する。時間経過や負の応答回数による自動解除、管理者向け強制解除はない。

# Runbook: 退職時 認証情報 失効チェックリスト

- 準拠: ADR-0012（退職失効は稼働と独立）、F-02（平文パスワード台帳）、F-03（管理方式）
- **重要**: 秘密値（パスワード／トークン／実メールアドレス）を本書・コミット・ログに書かない。記録するのは **サービス名・キー名・保存場所・公開ハンドル・所有権・実施者・日時** のみ。
- 実施タイミング: 新システムの完成・稼働と**独立**。退職者が参照できた認証情報は退職日までに完了。

## 1. 棚卸し（対象特定）

- [ ] 退職者が参照可能だった認証情報を列挙（サービス名・キー名・保存場所のみ）
- [ ] 動画に無関係な管理者系（hacomono／WordPress／採用／予約）を**前倒し対象**として分離
- [ ] 平文台帳（`10_必要情報` / `URL,PW管理`）の該当行を特定
- [ ] 会社管理の予備管理者、復旧メール、MFA、復旧コードの管理者を確認

## 2. 失効・再発行（値は扱わない）

- [ ] 各シークレット／トークン／パスワードを失効・再発行（担当＝権限者。値はチャット・文書・ログに出さない）
- [ ] 退職者の共有権限・管理者権限を削除
- [ ] 既存ログインセッション、アプリパスワード、APIトークン、OAuth同意を失効
- [ ] 共有パスワードを変更し、MFA・復旧先を会社管理へ更新
- [ ] 支部別OAuth（YouTube／Instagram）が存在し、退職者がアクセス可能だった場合は再認可（8＋総合）
- [ ] GAS↔Worker共有secret・R2キー・LINE secret 等が存在し、退職者がアクセス可能だった場合は再発行（キー名のみ記録）

## 3. 所有権移管

- [ ] 外部A/B/C所有資産（本体シート／Drive／GAS／各フォルダ）の自社アカウントへの移管方針を確認
- [ ] 会社管理アカウントへ所有権を移し、会社管理の予備管理者を設定
- [ ] 新しい秘密の保存先を用途別に分離（人間用パスワード／アプリ実行秘密／OAuthトークン）

## 4. 台帳是正

- [ ] 平文台帳から該当認証情報を削除・保管庫へ移行
- [ ] 非秘密の設定のみ招待制シートに残す（実秘密は保管庫）

## 5. 動作確認

- [ ] 新しい認証情報で投稿・承認・通知が成功することを確認（テスト環境／非公開）
- [ ] 旧認証情報が失効していることを確認

## 6. 記録

- [ ] 実施者・日時・対象（キー名レベル）を記録し完了報告
- [ ] 復旧先（所有者・再発行手順の所在）を明記

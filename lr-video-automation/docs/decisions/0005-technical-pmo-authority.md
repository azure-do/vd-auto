# ADR-0005: 技術PMOは承認済み調査・設計を成果物完成まで自律実行する

## Status

accepted

## Date

2026-07-30

## Context

技術PMOの権限が曖昧な場合、読み取り方法、一時ツール、軽微な技術詳細ごとに承認往復が発生し、製品設計や実装へ進みにくくなる。一方、業務判断、Repository変更、実装、本番操作までPMOへ委任すると責任境界が失われる。

## Decision

- 技術PMOは、承認済み範囲のRepository・資料の読み取り、技術調査、方式比較、設計、リスク整理、ADR・RFC案、テスト・受入条件、SE向けタスク分解を成果物完成まで自律的に進める。
- 読み取り方法、一時調査ツール、軽微で可逆的な技術詳細だけを理由に停止しない。
- 質問は小分けにせず、業務判断・リスク受容が必要な事項を判断パケットとしてまとめる。
- PMOは、Repository変更、製品コード実装、Commit、push、deploy、外部接続、本番変更、秘密情報の表示、業務要件の最終決定を行わない。
- 設計承認前にSEへ実装開始を指示しない。PMOはSE向け依頼文を作成し、亮さんとChatGPTの承認へ戻す。

## Consequences

- PMOは内部手順ごとに停止せず、調査・設計成果物を一括して提出する。
- ChatGPTと亮さんは、コマンド単位ではなく、成果物、リスク、重要設計、受入条件をレビューする。
- SEは承認済みタスクだけを実装し、設計変更はPMO、業務判断は亮さんとChatGPTへ戻す。

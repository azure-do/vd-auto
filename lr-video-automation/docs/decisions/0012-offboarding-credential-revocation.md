# ADR-0012: 退職時の認証情報失効は新システム稼働と独立に実施する

## Status

accepted

## Date

2026-07-30

## Context

F-02のとおり、支部Googleアカウント／YouTube／Instagram／TikTokに加え、hacomono管理画面・WordPress管理・採用系・予約系まで、ID・パスワードが平文でスプレッドシートに集約・共有され、複数支部で使い回しがある。SNS担当者が2026年8月末に退職予定であり、退職者が参照できた認証情報は、新システムの稼働状況にかかわらず失効・変更する必要がある。

## Decision

- 退職に伴う認証情報の失効・変更・所有権移管は、**新システムの完成・稼働とは独立に実施** する。
- 退職者が参照できた認証情報は **退職日までに失効・変更** する。動画に無関係な管理者系（hacomono／WordPress／採用／予約）は **前倒し** で変更する。
- 手順は **秘密値を含まないチェックリスト** として管理する（docs/runbooks/offboarding-credential-revocation.md）。記録するのはサービス名・キー名・保存場所・公開ハンドル・所有権・実施者・日時のみ。
- 新しい秘密は用途別に分離して保管する（人間用パスワード／アプリ実行秘密／OAuthトークン）。非秘密の設定のみ招待制シートに残す（F-03）。

## Consequences

- 退職連動のセキュリティ対応が開発進捗に依存しなくなる。
- 平文台帳（F-02）の該当行の削除・移行と、所有権の外部A/B/C→自社移管が運用タスクとして必要。
- チェックリストの完了記録（実施者・日時・対象＝キー名レベル）を残す。

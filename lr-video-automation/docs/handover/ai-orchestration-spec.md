# AIオーケストレーション仕様（提案・採否は実装側の判断）

- 出典: `docs/baseline/動画投稿自動化_AIオーケストレーション引継ぎ.md` からの抜粋
- 位置づけ: **提案であり要件ではない。** LLMを使わずに実装しても構わない
- 必須の制約は `product-brief.md` §11 を参照。本書の採否にかかわらず制約は適用される

## 1. 本書の扱い

システム構築にLLMを利用するかどうかは実装側の判断に委ねる。本書は、利用する場合に「どこまでをLLMに任せる想定か」を示したもので、この配分に従う義務はない。

ただし `product-brief.md` §11 の制約（決定的コードとの責務分離、LLMへトークン・投稿権限を渡さない）は、LLMを利用する限り必ず適用される。

## 2. LLMに任せることを想定している範囲

出力が人間の確認を経る、または誤っても決定的な処理に影響しない領域に限る。

| 対象 | 備考 |
|---|---|
| 投稿タイトル案 | 標準タイトル・希望タイトルと並ぶ選択肢の一つ。LINE承認画面で選択・編集される |
| 投稿文 | 同上 |
| ハッシュタグ | 表記揺れ（`KPOP` / `K-POP` / `kpop` 等）の解消を含む |
| 表記の正規化 | ジャンル末尾の「ダンス」重複など。決定的なルールで処理できる分はコード側で行う |
| 会話動画の字幕 | 会話がある動画のみ |
| 動画検査結果の説明 | 検査そのものは決定的コード。結果の文章化のみ |
| ハイライト候補 | Phase 8 以降。初期フェーズでは対象外 |

## 3. 責務分離の考え方

LLMの出力は**提案**として扱い、投稿の可否・投稿先・投稿実行そのものには関与させない。

```text
LLM   : 案を出す（タイトル・投稿文・ハッシュタグ・字幕）
  ↓
人間  : LINE承認画面で選択・編集・差し戻し
  ↓
コード: 承認された内容で投稿を実行（認証・冪等性・リトライ・ログ）
```

この分離により、LLMの出力品質が投稿の安全性に影響しない構造になる。

## 4. 実装上の注意

- LLMの応答を、そのまま外部APIへの入力として使わない。承認を経た版を使う。
- LLMの応答が空・不正形式でも、標準タイトル等のフォールバックで処理が継続すること。
- LLMの利用有無にかかわらず、承認済みコンテンツの版管理（ADR-0010）は必要。
- 生成AIツールに社内情報を投入する場合は、事前に使用ツールを共有すること。

# docs/handover — 外部共有用の派生文書

`docs/baseline/`（変更禁止の原本）から、社内の体制・依頼経緯・過去のインシデント記録を除き、**設計とゴールのみ**を抜き出した文書を置く。

外部委託者へ渡す想定の資料はここに集約する。原本と食い違った場合は `docs/baseline/` が正。

## 収録文書

| 文書 | 内容 | 扱い |
|---|---|---|
| [product-brief.md](product-brief.md) | 目的・講師UX・既存システム・媒体別方針・アーキテクチャ・データ設計・開発フェーズ・受入条件 | 要件 |
| [ai-orchestration-spec.md](ai-orchestration-spec.md) | LLMを利用する場合の適用範囲 | 提案。採否は実装側の判断 |

## baseline から除いた箇所

`動画投稿自動化_AIオーケストレーション引継ぎ.md` の以下を除外した。

- §1 ChatGPTへ最初に渡す依頼文（社内のAI体制・依頼経緯）
- §14 ChatGPTへ渡すべき資料（社内の運用手順）
- §15 末尾（過去チャットでのトークン平文掲載に関するインシデント記録）

秘密情報の禁止事項リスト（§15 本体）は、委託者にも必要なため `product-brief.md` §13 に残している。

## そのまま渡せる文書

以下は社内事情を含まないため、抜粋を作らず原本・現物をそのまま共有してよい。

- `docs/baseline/現行システム_仕様復元書.md` — 全編が現行仕様。列定義・タイトル/ハッシュタグ/概要欄の生成仕様・障害・推奨データ構造
- `docs/design/` — アーキテクチャ概要、MVPスコープ、実装単位（E-0〜E-7）
- `docs/contracts/` — 共通ID・イベント・状態
- `docs/decisions/` — ADR
- `docs/open-questions.md` — 未決事項の最新状態

## 更新時

baseline は変更されない前提のため、本ディレクトリの文書も原則として更新不要。設計が変わった場合は `docs/design/` と ADR が正となり、本ディレクトリは初期共有用の位置づけにとどまる。

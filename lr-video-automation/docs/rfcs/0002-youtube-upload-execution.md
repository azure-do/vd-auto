# RFC-0002: YouTube投稿の実行方式

- **Status: open**（規約準拠3値 `open`/`resolved`/`rejected` の `open`）
  - 本文で明記: **方式=B は確定**（ADR-0013）／**外部実行環境の製品は未決**。製品を別ADRで確定した時点で本RFCを `resolved` にする。
- 関連: ADR-0013（B方式採用・ADR-0009をsupersede予定）、ADR-0008（状態正本）、ADR-0012（秘密管理）、共通契約 v1（結果不明状態）
- 決定時期: 製品は数値ベース比較（§2）→ 根拠が揃えば別ADR。根拠なしに製品を確定・推奨しない。
- 注意: 外部接続を伴う実証は亮さんの明示承認後（SEが実施）。

## 背景

R2の元動画をYouTubeへ投稿する経路を E-0a で実証（ChatGPT受入、亮さん判断でB方式採用、ChatGPT監査差戻し→v2対応）。新規RFCを作らず本RFCを更新する。一次証跡は `docs/reports/E-0a-youtube-upload-poc.md`。

## 2. 外部実行基盤の数値比較（14件/日・要計測。根拠なしに確定/推奨しない）

> 以下の各列を**実測・実仕様の数値**で埋めるまで製品を確定も推奨もしない。現時点は全て `要計測`／`要確認`。
> 前提規模: 約14件/日、動画サイズ帯 20MB / 60MB / 300MB（実動画サイズ）。

| 評価軸（列） | Cloudflare内実行（Containers/Workers等） | Google Cloud Run | 常設VM/コンテナ | 計測方法 |
|---|---|---|---|---|
| 実動画サイズ上限（20/60/300MB可否） | 要計測 | 要計測 | 要計測 | 各サイズprivate投稿の成否 |
| 実行時間（1本あたり／上限） | 要確認（実行時間上限） | 要確認（リクエスト/ジョブ上限） | 実質無制限 | 60/300MBの送信+完了確認の実測 |
| Range/stream取得（R2→ストリーミング可否） | 要確認 | 要確認 | 可 | R2 Range GET でのストリーム送信検証 |
| ephemeral disk（一時ディスク容量） | 要確認 | 要確認（既定容量） | ディスク依存 | 300MBを一時保存 or ストリームで回避可か |

> 数値が揃うまで**第一候補を置かない**。過去案の「Cloudflare内実行を第一候補／Cloud Run代替」という推奨は**撤回**する（根拠不足のため）。

## 3. Cloudflareとの境界・R2からの取得方法

- 外部実行環境がCloudflare内なら R2バインディング/内部取得で境界最小・egress最小（実仕様は§2で要確認）。
- Cloudflare外なら R2署名URL または S3互換API取得（egress費・経路増）。**Range GET によるストリーム取得**を優先し、300MBの全量ローカル保存を避ける。
- 署名URL全文・R2資格情報は秘密（§5）。

## 4. YouTube処理完了確認・中断再開（共通契約準拠）

- 完了判定は `uploadStatus=processed` かつ `processingStatus=succeeded` かつ `privacyStatus=private`（共通契約 3.1）。
- 中断時は committed offset から再送（全量再送しない）。結果不明時は `OUTCOME_UNKNOWN → RECONCILIATION_REQUIRED`、**再セッション禁止条件**を適用。
- `yt_resumable_session_uri` は暗号化保存・非表示・非記録。期限切れ時は照合後にのみ再セッション。

## 5. 秘密管理と再認可

- OAuthトークン・client secret・R2資格情報・session URI を承認済み秘密保管場所に用途別分離で保管（ADR-0012）。
- 8支部＋総合の再認可（更新・失効）運用。表示・記録しない（ログマスキング確認）。

## 6. 製品決定に必要な最小実証（数値取得のため・承認後）

- **E-0a-2（最小・承認後）**: 候補製品でテストチャンネルへ 60MB / 300MB を**中断→committed offsetから再開**込みで private 投稿し、§2の各列（実行時間・Range/stream・ephemeral disk・egress・月額・監視）を**実測**。
- 目的は§2表の数値を根拠として埋めること。これ以上の広域実証は行わない（乱立回避）。
- 実施は亮さんの明示承認後（SE）。本RFCでは着手しない。

## 結論

方式=B 確定（ADR-0013）。製品は§2を**数値で**埋めた上で別ADRで確定する。現時点で製品の確定・推奨はしない（Status=open）。

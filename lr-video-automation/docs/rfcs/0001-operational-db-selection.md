# RFC-0001: 運用DB製品の選定

- Status: resolved（ADR-0015）
- 関連: ADR-0008（状態正本は運用DB・DLQ必須）
- 決定権限: SEが技術比較して選定し、RFC更新＋ADRへ理由を記録する。Codexレビュー後、E-1実装へ進む
- 停止条件: 新しい有料サービス、Cloudflare外の追加基盤、状態正本方針の変更が必要な場合だけ亮さんへ戻す

## 背景

ADR-0008で「状態正本は運用DB、条件付き更新で排他、DLQ必須」を確定した。具体的なDB製品は比較後に決める。規模は約2,582件/6か月 ≈ 14件/日。最大スケールより運用単純性を優先する。

## 候補と評価軸

| 候補 | 長所 | 短所 |
|---|---|---|
| Cloudflare D1（SQLite） | Worker統合・SQL・低運用 | 書き込み特性・制限の確認要 |
| SQLite-backed Durable Objects | 単一オブジェクトで強整合・排他が容易 | 設計モデルの学習・分散時の考慮 |
| その他（外部マネージドDB等） | 機能・実績 | 別基盤の運用・認証・コスト |

評価軸: 条件付き更新/トランザクションの容易さ、Queue Consumerとの親和性、DLQ再処理との整合、運用単純性、コスト（付録: 規模14件/日）、バックアップ/監査。

## 検討事項

- 冪等台帳（`idempotency_key`）と状態遷移を同一トランザクションで扱えるか。
- Sheetsミラーへの同期方法（正本→表示の一方向）。
- 監査ログ（実行者・日時、承認・削除）の保持。

## 結論

Cloudflare D1（SQLite）を採用する。理由と制約はADR-0015を正本とする。

- D1の`batch()`と条件付き更新で、状態遷移・冪等台帳・監査ログ・ミラーoutboxを同一トランザクションで扱う。
- 約14ジョブ/日の中央台帳では、ジョブ単位ルーティングや横断集約が必要なDurable ObjectsよりD1の方が単純。
- Cloudflare実環境のresourceは作成せず、E-1はMiniflareのlocal / fakeで検証する。

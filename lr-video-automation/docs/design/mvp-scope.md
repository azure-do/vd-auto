# MVPスコープと暫定方式の終了条件

- Status: accepted
- 方針: 社内向けMVPをまず作り継続アップデート。初期に完成形・過剰分散を求めない。ただし後戻りコスト・事故影響の大きい基盤は初期から担保する。

## 1. 基盤（初期担保）と可変部（後回し可）

| 区分 | 対象 | 理由 |
|---|---|---|
| **基盤＝初期担保** | 本人確認(OIDC+sub) / 秘密管理(用途別分離・退職失効独立) / 動画検証(入口・前倒し) / 承認(承認済み版固定) / 冪等性(job+投稿先+承認版) / 状態履歴(運用DB正本+監査ログ) / ロールバック(機能フラグ+収束手順) | 後から差し替えるとデータ/認証/公開事故に直結。設計に織り込むコストが最小 |
| **可変部＝後回し/手動可** | SNS加工 / Instagram自動投稿 / TikTok自動投稿 / 媒体・支部の一括展開 / 監視自動化 / SEO連携 / AI編集 | 手動や後続追加で代替でき、事故時の影響が限定的 |

> 手動代替は基盤を迂回しない。手動投稿でも検証・承認・状態記録・冪等・監査は自動で通す。

## 2. スコープ・マトリクス（初期MVP / 手動代替 / 将来）

| 機能領域 | 初期MVPで実装 | MVP時点は手動代替 | 将来アップデート | 基盤 |
|---|---|---|---|---|
| 本人確認 | Google OIDC＋teacher_id↔sub、トークン検証 | （迂回不可） | 誤紐付け解除UI高度化 | ★ |
| 秘密管理 | 用途別分離、退職失効を稼働と独立 | 台帳棚卸しは人手 | 自動ローテ | ★ |
| 動画検証 | 入口で MIME/形式/サイズ/読取/チェックサム/重複 | （迂回不可） | 内容検査高度化 | ★ |
| クラス判定 | read model照合、0/1/多、CLASS_UNRESOLVED隔離＋通知 | 未確定・代講・臨時は本部が手動確定 | 当日予定からの精緻な自動確定 | 準★ |
| 状態・履歴 | 運用DB=正本、監査ログ、Queue+DLQ | DLQ再処理・異常は手動監視 | 監視/アラート自動化・ダッシュボード | ★ |
| 冪等性 | job+投稿先+承認済み版、試行番号別 | （迂回不可） | — | ★ |
| 承認(LINE) | 単一入口、承認済み版固定、多重押下冪等、allowlist | 承認者追加/失効は手動 | 権限管理の高度化 | ★ |
| YouTube投稿 | private無条件・1〜2支部パイロット（B方式=外部runner・ADR-0013） | 公開/OAuth更新は手動 | 8＋総合展開・公開対応（別単位） | 準★ |
| SNS加工 | 加工なし（YouTubeは元動画） | 必要時は手動編集 | 加工基盤(RFC-0003)・字幕・焼込 | 可変 |
| Instagram | （MVP対象外を推奨） | 加工版を手動投稿 | Graph API自動 | 可変 |
| TikTok | 状態設計のみ（手動フロー） | 手動パッケージ→アプリ投稿・URL登録 | 受信箱API→Direct Post | 可変 |
| ロールバック | 機能フラグ切替・収束手順 | 切替判断は人手ゲート | 自動ヘルスチェック連動 | ★ |
| 監視/運用 | 最低限のエラーログ・状態可視化 | DLQ/失敗/トークン期限は手動確認 | アラート・自動再認証・ダッシュボード | 可変 |
| SEO/DM連携 | MVP非対象（境界のみ定義） | — | イベント契約で連携 | 可変 |

## 3. MVP完成の定義（社内向け）

`E-0 技術実証 → MVP-Core → MVP-Publish`。
= 「講師が提出 → OIDC本人確認 → 入口で検証 → クラス確定（例外は本部手動）→ LINE承認 → 支部YouTubeへ非公開投稿。状態・冪等・監査・ロールバックが担保」。IG/TikTok/加工は手動代替 or 後続。

## 4. 暫定方式の終了条件・移行先

| 暫定方式 | 終了条件（満たしたら移行） | 移行先 |
|---|---|---|
| YouTube GAS+Drive（A2案） | — | 不採用（E-0aでB方式採用・ADR-0013）。本行は非該当 |
| YouTube private（無条件） | API監査通過 ＋ Q12（公開設定・時刻）決定 ＋ 亮さん承認 | 公開対応の別実装単位（監査フラグ単独では公開しない） |
| YouTube 1〜2支部パイロット | 受入充足・突合一致 | 8＋総合展開 |
| SNS加工なし | IG/TikTok展開Go判断 | 加工基盤(RFC-0003 C) |
| Instagram手動 | Professional確認＋API検証(E-0b) | Graph API自動 |
| TikTok手動 | 件数増＋審査/受信箱適合 | 受信箱API→Direct Post |
| 監視=手動(Sheets/DLQ目視) | 件数増/夜間負荷増 | アラート・自動再処理 |
| 承認者=手動allowlist | 承認者増/支部委譲 | 権限管理の仕組み化 |
| クラス未確定=本部手動確定 | 例外が定型化 | 代講/臨時の自動判定 |
| 保存=一律30日(暫定) | 運用実績で妥当性検証 | 媒体別/種別の保存ポリシー精緻化 |
| 秘密=台帳手動棚卸し | 分離保管が定着 | シークレット自動ローテ |

各終了条件は受入条件／監視指標にひも付け、達成時にRFC/ADRで移行を起票する。
